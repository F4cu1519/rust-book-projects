TRAITS EN RUST
==============

INTRODUCCIÓN
------------

Los traits son una de las características más poderosas de Rust. Definen funcionalidad
compartida que diferentes tipos pueden implementar. Son similares a las interfaces en
otros lenguajes, pero con características únicas de Rust.

Un trait define un conjunto de métodos que un tipo debe implementar. Le dice al compilador
"estos tipos pueden hacer estas cosas" y permite escribir código genérico que funciona
con cualquier tipo que implemente ese trait.


¿QUÉ ES UN TRAIT?
-----------------

DEFINICIÓN:
Un trait es una colección de métodos definidos para un tipo desconocido: Self.
Especifica comportamiento que puede ser compartido entre diferentes tipos.

ANALOGÍAS:
- Como una interfaz en Java/C#
- Como un protocolo en Swift
- Como una type class en Haskell

PROPÓSITO:
- Definir comportamiento compartido de manera abstracta
- Permitir polimorfismo
- Restringir tipos genéricos a aquellos que tienen cierta funcionalidad


DEFINIR UN TRAIT
-----------------

SINTAXIS BÁSICA:

    trait Summary {
        fn summarize(&self) -> String;
    }

COMPONENTES:
- `trait` keyword: declara un nuevo trait
- `Summary`: nombre del trait (CamelCase por convención)
- Métodos dentro del bloque (pueden tener implementación por defecto o no)


EJEMPLO COMPLETO:

    pub trait Summary {
        fn summarize(&self) -> String;
    }

Esto dice: "Cualquier tipo que implemente Summary debe proporcionar un método
summarize que tome &self y devuelva un String"


IMPLEMENTAR UN TRAIT
---------------------

SINTAXIS:

    impl TraitName for TypeName {
        // implementación de métodos
    }

EJEMPLO:

    pub struct NewsArticle {
        pub headline: String,
        pub location: String,
        pub author: String,
        pub content: String,
    }

    impl Summary for NewsArticle {
        fn summarize(&self) -> String {
            format!("{}, by {} ({})", self.headline, self.author, self.location)
        }
    }

    pub struct Tweet {
        pub username: String,
        pub content: String,
        pub reply: bool,
        pub retweet: bool,
    }

    impl Summary for Tweet {
        fn summarize(&self) -> String {
            format!("{}: {}", self.username, self.content)
        }
    }

USO:

    let tweet = Tweet {
        username: String::from("horse_ebooks"),
        content: String::from("of course, as you probably already know, people"),
        reply: false,
        retweet: false,
    };

    println!("1 new tweet: {}", tweet.summarize());


IMPLEMENTACIONES POR DEFECTO
-----------------------------

Los traits pueden proporcionar implementaciones por defecto para algunos o todos sus métodos.

SINTAXIS:

    pub trait Summary {
        fn summarize(&self) -> String {
            String::from("(Read more...)")
        }
    }

USAR LA IMPLEMENTACIÓN POR DEFECTO:

    impl Summary for NewsArticle {}

    let article = NewsArticle { /* ... */ };
    println!("New article: {}", article.summarize());  // Imprime: (Read more...)

SOBRESCRIBIR LA IMPLEMENTACIÓN POR DEFECTO:

    impl Summary for Tweet {
        fn summarize(&self) -> String {
            format!("{}: {}", self.username, self.content)
        }
    }


MÉTODOS QUE LLAMAN A OTROS MÉTODOS:

    pub trait Summary {
        fn summarize_author(&self) -> String;

        fn summarize(&self) -> String {
            format!("(Read more from {}...)", self.summarize_author())
        }
    }

    impl Summary for Tweet {
        fn summarize_author(&self) -> String {
            format!("@{}", self.username)
        }
        // summarize() usa la implementación por defecto
    }


TRAITS COMO PARÁMETROS
-----------------------

SINTAXIS BÁSICA:

    pub fn notify(item: &impl Summary) {
        println!("Breaking news! {}", item.summarize());
    }

Esto significa: "acepta cualquier tipo que implemente el trait Summary"

USO:

    notify(&tweet);
    notify(&article);


TRAIT BOUND SYNTAX:

Una forma más explícita y potente:

    pub fn notify<T: Summary>(item: &T) {
        println!("Breaking news! {}", item.summarize());
    }

DIFERENCIA:
- `impl Trait`: sintaxis simple, para casos básicos
- `<T: Trait>`: trait bound, más flexible y expresivo


MÚLTIPLES TRAITS:

    pub fn notify(item: &(impl Summary + Display)) {
        // item debe implementar AMBOS traits
    }

    // O con trait bound syntax:
    pub fn notify<T: Summary + Display>(item: &T) {
        // ...
    }


WHERE CLAUSES
-------------

Cuando los trait bounds se vuelven complejos, usa `where` para mayor claridad:

SIN WHERE (difícil de leer):

    fn some_function<T: Display + Clone, U: Clone + Debug>(t: &T, u: &U) -> i32 {
        // ...
    }

CON WHERE (más claro):

    fn some_function<T, U>(t: &T, u: &U) -> i32
    where
        T: Display + Clone,
        U: Clone + Debug,
    {
        // ...
    }


RETORNAR TIPOS QUE IMPLEMENTAN TRAITS
--------------------------------------

SINTAXIS:

    fn returns_summarizable() -> impl Summary {
        Tweet {
            username: String::from("horse_ebooks"),
            content: String::from("of course, as you probably already know, people"),
            reply: false,
            retweet: false,
        }
    }

IMPORTANTE - LIMITACIÓN:
Solo puedes usar `impl Trait` si retornas UN SOLO TIPO:

    fn returns_summarizable(switch: bool) -> impl Summary {
        if switch {
            NewsArticle { /* ... */ }  // ERROR!
        } else {
            Tweet { /* ... */ }        // No puedes retornar tipos diferentes
        }
    }

Para retornar diferentes tipos, necesitas usar trait objects (tema avanzado).


TRAIT BOUNDS CON GENÉRICOS
---------------------------

Combinar traits con genéricos es muy poderoso:

    fn largest<T: PartialOrd>(list: &[T]) -> &T {
        let mut largest = &list[0];
        
        for item in list {
            if item > largest {
                largest = item;
            }
        }
        
        largest
    }

Sin el trait bound `PartialOrd`, el código no compila porque no todos los tipos
tienen el operador `>`.


IMPLEMENTACIONES CONDICIONALES:

    struct Pair<T> {
        x: T,
        y: T,
    }

    impl<T> Pair<T> {
        fn new(x: T, y: T) -> Self {
            Self { x, y }
        }
    }

    // Este método solo existe si T implementa Display + PartialOrd
    impl<T: Display + PartialOrd> Pair<T> {
        fn cmp_display(&self) {
            if self.x >= self.y {
                println!("The largest member is x = {}", self.x);
            } else {
                println!("The largest member is y = {}", self.y);
            }
        }
    }


BLANKET IMPLEMENTATIONS
------------------------

Implementaciones para cualquier tipo que cumpla ciertos bounds:

    impl<T: Display> ToString for T {
        fn to_string(&self) -> String {
            // ...
        }
    }

Esto significa: "cualquier tipo que implemente Display automáticamente implementa ToString"

Por eso puedes hacer:

    let s = 3.to_string();  // i32 implementa Display, entonces tiene to_string()


REGLA DEL HUÉRFANO (ORPHAN RULE)
---------------------------------

Solo puedes implementar un trait en un tipo si:
- El trait está definido en tu crate, O
- El tipo está definido en tu crate

NO PUEDES:

    // ERROR: Vec y Display son externos
    impl Display for Vec<i32> {
        // ...
    }

PUEDES:

    // OK: Summary es tuyo
    impl Summary for Vec<i32> {
        // ...
    }

    // OK: Tweet es tuyo
    impl Display for Tweet {
        // ...
    }


TRAITS DERIVABLES
-----------------

Rust proporciona traits que pueden implementarse automáticamente con `#[derive]`:

    #[derive(Debug, Clone, PartialEq)]
    struct Point {
        x: i32,
        y: i32,
    }

TRAITS DERIVABLES COMUNES:
- Debug: permite imprimir con {:?}
- Clone: permite clonar valores
- Copy: tipos que se copian en vez de moverse
- PartialEq y Eq: comparación de igualdad
- PartialOrd y Ord: comparación de orden
- Hash: hashear valores


TRAITS IMPORTANTES DE LA BIBLIOTECA ESTÁNDAR
---------------------------------------------

DISPLAY:
    impl Display for Point {
        fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
            write!(f, "({}, {})", self.x, self.y)
        }
    }

ITERATOR:
    impl Iterator for Counter {
        type Item = u32;
        
        fn next(&mut self) -> Option<Self::Item> {
            // ...
        }
    }

FROM y INTO:
    impl From<i32> for Number {
        fn from(item: i32) -> Self {
            Number { value: item }
        }
    }
    
    let num = Number::from(30);
    let num: Number = 30.into();  // Into se implementa automáticamente

DROP:
    impl Drop for MyType {
        fn drop(&mut self) {
            println!("Cleaning up!");
        }
    }


TIPOS ASOCIADOS
---------------

Los traits pueden tener tipos asociados:

    pub trait Iterator {
        type Item;  // Tipo asociado
        
        fn next(&mut self) -> Option<Self::Item>;
    }

USO:

    struct Counter {
        count: u32,
    }

    impl Iterator for Counter {
        type Item = u32;  // Especificamos el tipo asociado
        
        fn next(&mut self) -> Option<Self::Item> {
            self.count += 1;
            if self.count < 6 {
                Some(self.count)
            } else {
                None
            }
        }
    }

DIFERENCIA CON GENÉRICOS:
- Tipos asociados: solo una implementación por tipo
- Genéricos: múltiples implementaciones posibles

    // Con genérico: puedes implementar Add<Point> y Add<i32>
    impl Add<Point> for Point { /* ... */ }
    impl Add<i32> for Point { /* ... */ }
    
    // Con tipo asociado: solo una implementación
    impl Iterator for Counter { /* ... */ }


SUPERTRAITS
-----------

Un trait puede requerir que otro trait esté implementado:

    trait OutlinePrint: Display {
        fn outline_print(&self) {
            println!("* {} *", self);  // Puede usar Display
        }
    }

Para implementar OutlinePrint, el tipo DEBE implementar Display primero.


PATRONES COMUNES
----------------

BUILDER PATTERN:

    trait Builder {
        type Output;
        fn build(self) -> Self::Output;
    }

STRATEGY PATTERN:

    trait CompressionStrategy {
        fn compress(&self, data: &[u8]) -> Vec<u8>;
    }

ADAPTER PATTERN:

    trait Target {
        fn request(&self) -> String;
    }


RESUMEN Y PUNTOS CLAVE
-----------------------

✓ Los traits definen comportamiento compartido
✓ Son como interfaces pero más potentes
✓ Permiten polimorfismo y abstracción
✓ Se pueden usar como parámetros y valores de retorno
✓ Trait bounds restringen tipos genéricos
✓ Las implementaciones pueden ser condicionales
✓ Algunos traits se pueden derivar automáticamente
✓ La regla del huérfano previene conflictos
✓ Los tipos asociados son más específicos que los genéricos

PRÓXIMOS PASOS:
- Practicar creando tus propios traits
- Combinar traits con genéricos
- Estudiar trait objects para casos avanzados
- Aprender sobre lifetimes en traits
